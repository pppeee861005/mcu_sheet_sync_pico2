# MCU 與 Google 試算表通訊開發計畫書 (mcu_sheet_sync)

## 1. 專案目標與願景
- **核心目標**：實現 ESP32-S3 微控制器通電開機後，自動連接 Wi-Fi（支援家用與手機熱點自動切換），在 SSD1306 OLED 螢幕上顯示「待機中」。當使用者按下實體按鍵（GPIO 18）時，MCU 透過 HTTP POST 發送數據到 Google Apps Script (GAS)，自動將一筆記錄寫入 Google 試算表（Google Sheets），並在螢幕顯示「寫入成功」後重返待機狀態。
- **架構特點**：輕量化、免在 MCU 執行繁重 OAuth 憑證、高容錯性、具備即時硬體視覺回饋。

---

## 2. 系統架構與流程

### 2.1 軟硬體組成
- **主控端**：ESP32-S3 DevKitC-1 (MicroPython)
- **顯示器**：0.96 吋 SSD1306 OLED (I2C: SDA=GPIO21, SCL=GPIO22, 128x64)
- **輸入端**：實體按鈕 (GPIO 18, 內部上拉，按下為 LOW)
- **雲端轉發層**：Google Apps Script (GAS) 部署為公開 Web App
- **雲端資料庫**：Google Sheets 試算表

### 2.2 狀態轉換流程 (FSM)
```text
  [ POWER ON ]
       │
       ▼
[ Wi-Fi 連線輪詢 ]
  ├─ 優先：egg5630 (家用)
  └─ 備援：Redmi 13C (手機熱點)
       │
       ▼
 [ 待機狀態 (Standby) ] ◄─────────────────┐
       │                                  │
  (按鍵 GPIO 18 按下)                      │ (延遲 2 秒)
       │                                  │
       ▼                                  │
[ 上傳數據至 Google Sheet ]                │
       │                                  │
       ▼                                  │
[ 顯示結果 (Success / Failed) ] ──────────┘
```

### 🚩 Milestone 3：燒錄與實體驗證 (Board-level Smoke Test)
- [ ] **M3.1 偵測 COM 埠**：
  - 執行 `mpremote devs`，確認 ESP32-S3 已識別（預期為 `COM3` 或 `COM4`）。
- [ ] **M3.2 燒錄驅動與程式碼**：
  - 上傳 `ssd1306.py` 至板子：`mpremote connect COMx cp ssd1306.py :ssd1306.py`
  - 上傳 `main.py` 至板子：`mpremote connect COMx cp main.py :main.py`
- [ ] **M3.3 通電與功能驗證**：
  - 軟體重啟板子：`mpremote connect COMx reset`
  - 檢驗 1：開機時是否能自動連線家用 Wi-Fi（若關閉則能切換至手機熱點）。
  - 檢驗 2：螢幕是否正確顯示 `[ Standby ]` 待機畫面。
  - 檢驗 3：按下按鈕時，螢幕是否顯示 `Sending Data...` ➔ `Upload Success!`。
  - 檢驗 4：檢視 Google Sheet 是否成功新增資料行。

### 🚩 Milestone 4：玩法升級與進階功能擴充 (Gameplay & Feature Upgrades)
- [ ] **M4.1 雙向通訊與雲端控制 (Cloud-to-MCU 反向控制)**：
  - 在 GAS 中實作 `doGet(e)` 端點，讓試算表特定儲存格（例如 `B2`）作為控制指令旗標（如：`LED_ON` / `LED_OFF` 或跑馬燈留言文字）。
  - MCU 定時輪詢 GET 取得指令，控制板載 LED 或將 Google Sheet 留下的文字直接即時投射在 OLED 螢幕上！
- [ ] **M4.2 環境即時監測儀與雲端自動繪圖 (Auto Data Logger & Charting)**：
  - 接上感測器（如 DHT11 溫濕度或土壤濕度感測器）。
  - MCU 設定 Timer 每 5~10 分鐘自動採樣並 POST 上傳至試算表。
  - 在 Google Sheet 設定自動折線圖與條件格式警示（例如溫度 > 30°C 自動變紅底）。
- [ ] **M4.3 實體多功能生活打卡盒 (Physical Habit Tracker & Attendance)**：
  - 增加按鍵功能（短按、長按、雙擊），代表不同事件（例如：短按「喝水打卡」、長按「讀書 30 分鐘完成」、雙擊「運動打卡」）。
  - Google Sheet 自動統計當日打卡次數、熱量或時數，並在 OLED 即時反饋今日已打卡累計次數。
- [ ] **M4.4 斷線防護與離線快取佇列 (Offline Queue Buffer)**：
  - 當 Wi-Fi 暫時斷線時，按鍵打卡數據先存在 MCU 內部 Flash（快取佇列）。
  - 待連回 Wi-Fi 後自動批量補傳 (Sync Backlog)，避免資料丟失。

## 4. 驗收標準 (Definition of Done)
1. **無手動修改網路**：MCU 攜帶至手機熱點環境，不改 code 即可連網。
2. **待機與視覺回饋清楚**：未按鍵前維持「待機中」，按鍵後螢幕有明顯狀態切換。
3. **數據精確寫入**：按下實體按鈕 1 次，Google 試算表即精準新增 1 筆紀錄且次數遞增。
