# AIoT LED V0.1 計劃書

## 一、專案目標

讓 AI 透過自然語言控制 Pico 2 W 上的 WS2812 LED Ring，完成第一版 AIoT 控制流程：

```text
自然語言 → AI 判斷 → LED_ON／LED_OFF → 雲端命令 → Pico → WS2812
```

V0.1 只處理「開燈」與「關燈」，先建立穩定、可驗證的 AI 控制鏈。

## 二、目前 IoT 基礎

現有系統如下：

```text
網頁按鈕 → Vercel → Upstash → Pico 2 W → WS2812
```

Pico 2 W 會透過 Wi-Fi 定期向雲端取得命令，再控制 WS2812 LED Ring。

WS2812 接線：

- Pico GP0 → WS2812 DIN／DATA IN
- Pico GND → WS2812 GND
- 電源 → WS2812 VCC

## 三、AIoT V0.1 架構

```text
使用者自然語言
        ↓
AI 指令解析 API
        ↓
標準化硬體命令
        ↓
Upstash 命令儲存
        ↓
Pico 2 W 輪詢命令
        ↓
WS2812 LED Ring
```

AI 不直接操作 GPIO，只能輸出系統允許的標準命令。Pico 只執行白名單內的命令。

## 四、V0.1 支援命令

| 使用者說法 | AI 轉換命令 | 燈光動作 |
|---|---|---|
| 請開燈、亮燈、啟動燈光 | `LED_ON` | WS2812 亮紅燈 |
| 請關燈、熄燈、停止燈光 | `LED_OFF` | WS2812 熄滅 |

無法辨識的內容不得控制硬體，API 應回覆「無法理解目前只支援開燈或關燈」。

標準命令格式：

```json
{
  "command": "LED_ON"
}
```

或：

```json
{
  "command": "LED_OFF"
}
```

## 五、API 規劃

新增 AI 指令入口：

```text
POST /api/ai-command
```

請求內容：

```json
{
  "message": "請幫我開燈"
}
```

API 工作流程：

1. 接收使用者自然語言。
2. 交給 AI 判斷使用者意圖。
3. 將意圖限制為 `LED_ON` 或 `LED_OFF`。
4. 將標準命令寫入 Upstash。
5. 回傳 AI 判斷結果與執行命令。

回應範例：

```json
{
  "success": true,
  "reply": "已幫你開燈。",
  "command": "LED_ON"
}
```

## 六、Pico 程式需求

Pico 端沿用目前的 Wi-Fi 與雲端輪詢機制，並確認只接受：

- `LED_ON`
- `LED_OFF`

其他命令一律忽略，不直接執行。

目前 WS2812 狀態顯示也保留：

- 啟動／有電源：藍色
- 等待 Wi-Fi：黃色
- Wi-Fi 已連線：綠色
- 待命中：白色
- 無法取得 Wi-Fi：紫色
- 收到 `LED_ON`：紅色
- 收到 `LED_OFF`：熄滅

## 七、開發階段

### 階段 1：確認現有 IoT 控制

- 確認網頁按鈕可以寫入 `LED_ON`。
- 確認 Pico 可以取得命令。
- 確認 WS2812 可以正確亮燈與熄滅。

### 階段 2：建立 AI 指令 API

- 新增 `/api/ai-command`。
- 接收自然語言文字。
- 將「開燈」與「關燈」轉換成標準命令。
- 將命令寫入既有的 Upstash 結構。

### 階段 3：串接與測試

- 測試「請開燈」。
- 測試「請關燈」。
- 測試無法辨識的指令。
- 確認 AI 指令與網頁按鈕可以共用 Pico 控制鏈。

## 八、驗收標準

以下測試全部通過，即完成 AIoT LED V0.1：

1. 輸入「請開燈」，WS2812 亮紅燈。
2. 輸入「請關燈」，WS2812 熄滅。
3. 輸入不支援的命令時，LED 狀態不改變。
4. Pico 斷線後重新連上 Wi-Fi，可以繼續取得命令。
5. AI 只能產生白名單內的硬體命令。
6. 原本的網頁按鈕控制仍然正常。

## 九、安全與限制

- 不讓 AI 直接執行任意 Python 或 GPIO 指令。
- API 金鑰、Wi-Fi 密碼與 Upstash 憑證不得提交到公開儲存庫。
- 所有 AI 輸出都必須經過命令白名單驗證。
- V0.1 不加入自動感測決策，先完成自然語言控制。

## 十、後續版本方向

- V0.2：支援燈光顏色與亮度，例如紅色、藍色、50%。
- V0.3：加入感測器資料，讓 AI 根據距離或環境狀態決策。
- V0.4：加入執行回報，讓 AI 知道 Pico 是否成功完成命令。
- V1.0：建立多裝置、多命令與權限管理。
