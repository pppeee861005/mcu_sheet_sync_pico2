# v1.0 Vercel Web App 開發計劃

## 目標

將 v0.1 Python LangChain Agent 部署至 Vercel，讓使用者透過手機瀏覽器與 Agent 對話並控制 AIoT LED。

## 系統架構

```text
手機瀏覽器
    ↓
Vercel Web App
    ↓
LangChain Agent API
    ↓
LED Tool／HTTP API
    ↓
Pico 2 W + WS2812 LED
```

## 功能範圍

- 手機友善聊天介面
- 開燈、關燈、查詢狀態
- `/api/chat` 後端入口
- Vercel Serverless Function
- API 請求載入與錯誤狀態
- Vercel Environment Variables 管理金鑰
- Production 網址

## 開發前提

- v0.1 本機 Agent 已完成並通過測試。
- LED HTTP API 可由雲端連線。
- 模型金鑰已準備，且不會寫入原始碼。
- 若使用 MCP，MCP Server 必須提供雲端可連線的 HTTP、SSE 或 Streamable HTTP 介面。

## 開發工作

1. 從 v0.1 抽離 Agent 核心與 LED Tools。
2. 建立 `/api/chat`，接收使用者訊息並回傳 Agent 回覆。
3. 建立簡單、適合手機的聊天頁面。
4. 設定 Vercel Environment Variables。
5. 建立 Vercel 部署設定。
6. 部署 Preview 版本。
7. 以手機驗證開燈、關燈與狀態查詢。
8. 驗證錯誤處理與安全限制。
9. 部署 Production 並完成部署紀錄。

## 測試案例

| 測試 | 預期結果 |
|---|---|
| 手機開啟網站 | 頁面正常載入 |
| 幫我開燈 | LED 開啟並顯示成功 |
| 幫我關燈 | LED 關閉並顯示成功 |
| 查詢狀態 | 顯示實際 LED 狀態 |
| API 失敗 | 顯示錯誤，不虛報成功 |
| 無關指令 | 拒絕執行 |
| 檢視前端程式 | 不包含模型金鑰 |

## 安全限制

- Agent 只能使用 LED 白名單工具。
- API 金鑰只能放在 Vercel Environment Variables。
- 前端不得直接呼叫需要秘密資訊的服務。
- 不提供 Shell、檔案系統或任意 HTTP 工具。
- 對聊天輸入與 API 回應設定合理的 timeout 與錯誤處理。

## 完成標準

- 手機可開啟 Production 網址。
- 三種 LED 操作皆可正常完成。
- Agent 回覆與實際 LED 狀態一致。
- Preview 與 Production 部署成功。
- 秘密資訊未暴露。
- 完成手機測試、部署紀錄與 README。

## 不列入 v1.0

- 使用者登入系統
- 多使用者權限
- 語音控制
- 多設備管理
- 排程與自動化
- 常駐背景 Agent
