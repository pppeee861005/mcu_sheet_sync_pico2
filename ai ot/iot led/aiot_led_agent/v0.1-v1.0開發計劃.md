# AIoT LED Control Agent：v0.1–v1.0 開發計劃

## 版本定位

```text
v0.0 Codex 版       概念驗證：手機 Remote 操作 PC Codex 控制 LED
v0.1 Python Agent   核心功能：本機 LangChain 專用 Agent
v1.0 Web App        使用者版本：Vercel 部署，手機直接操作
```

## 共同目標

建立一個只控制 AIoT LED 的 Agent，支援開燈、關燈與查詢狀態。沿用既有 LED Skill、MCP 與 HTTP API，不重做 Pico 2 W 與 WS2812 控制邏輯。

## v0.1：Python LangChain 最小 Agent

### 目標與範圍

- 在本機以 Python 執行 LangChain Agent。
- 建立 LED Tool：`on`、`off`、`status`。
- 優先直接呼叫既有 HTTP API，也可接入既有 MCP。
- 加入 timeout、HTTP 錯誤與 MCP 連線錯誤處理。
- Agent 只允許 LED 白名單操作。

### 預計檔案

```text
v0.1_python_agent/
├── main.py
├── led_tools.py
├── requirements.txt
├── .env.example
├── README.md
├── Agent行為規格.md
└── 測試紀錄.md
```

### 開發順序

1. 建立虛擬環境與依賴清單。
2. 將 `/api/on`、`/api/off`、`/api/command` 包裝成受限 Tool。
3. 建立 LangChain Agent、系統提示與命令列入口。
4. 加入錯誤處理與安全限制。
5. 完成功能、安全與失敗測試。
6. 記錄測試結果與已知問題。

### v0.1 測試與完成標準

| 測試 | 預期結果 |
|---|---|
| 開燈 | 呼叫 `on`，回報成功 |
| 關燈 | 呼叫 `off`，回報成功 |
| 查詢狀態 | 呼叫 `status`，回報 API 狀態 |
| 無關指令 | 拒絕且不呼叫工具 |
| API timeout／500 | 回報失敗，不宣稱 LED 已改變 |

完成條件：三種操作成功、LED 狀態一致、只能使用 LED Tool、金鑰不進入 Git。

## v1.0：Vercel Web App

### 目標與範圍

- 將 v0.1 Agent 核心部署至 Vercel。
- 提供手機友善聊天介面與 `/api/chat`。
- 使用 Vercel Environment Variables 保存金鑰。
- 顯示載入、成功與錯誤狀態。
- 完成 Preview、手機測試與 Production 部署。

### 預計檔案

```text
v1.0_web_app/
├── app/page.py
├── app/api/chat.py
├── agent.py
├── led_tools.py
├── requirements.txt
├── vercel.json
├── .env.example
├── README.md
└── 部署紀錄.md
```

### 開發順序

1. 從 v0.1 抽離 Agent 核心。
2. 建立後端聊天 API 與手機聊天頁面。
3. 設定 Vercel 環境變數。
4. 確認雲端可連線既有 LED HTTP API。
5. 部署 Preview，使用手機測試三種操作。
6. 修正問題後部署 Production，完成部署紀錄。

### v1.0 完成標準

- 手機可開啟 Production 網站。
- 可完成開燈、關燈與查詢狀態。
- 前端不暴露模型金鑰。
- API 失敗時顯示明確錯誤。
- 不支援指令會被拒絕。

## 技術決策與推進條件

優先使用既有 HTTP API 作為 LangChain Tool。若 MCP 提供雲端可連線的 HTTP、SSE 或 Streamable HTTP 介面，再加入 MCP Adapter。Vercel Function 不執行常駐程序或 Shell。

```text
v0.1 測試通過 → Web API → 手機介面 → Preview 測試 → Production v1.0
```
