🎮《餐餐機器人》開發計畫 v0.1

我建議「餐餐」定位成三個專案裡最先完成的作品。

CYD 2.8" Touch 整合板 → USB 燒入程式 → 開機就能使用。

第一代先做到一件事：

🎫 有 3 張餐券 → 按一下「使用餐券」→ 變 2 張 → 再按變 1 張 → 最後 0 張，而且斷電不會忘記。

5
一、餐餐的硬體

我們採取「整套優先」，所以直接使用 CYD 2.8" 240×320 Touch。

硬體	功能	數量
CYD 2.8" Touch	主機＋螢幕＋Touch	2片（1用1備）
USB Data Cable	燒錄＋供電	1～2
Active Buzzer	成功提示音	1
大型實體按鈕	第二階段使用	1
Breadboard	Debug	必要時才用

CYD 已經整合：

ESP32 + LCD + Touch + Wi-Fi/Bluetooth

所以第一版甚至不需要麵包板、不需要焊接、不需要另外買 TFT。

Phase 1｜先把 CYD 跑起來

貨到第一件事不是寫餐券程式。

而是：

USB 接電腦 → 燒官方 Demo → LCD 顯示 → Touch 測試。

確認：

☑ ESP32 可以燒錄
☑ LCD 正常
☑ Touch 正常
☑ USB Data 正常

四個都成功：

M0 完成。

Phase 2｜做最簡單的餐券機

先不要動畫、不要 Wi-Fi、不要 AI。

只做：

┌──────────────────────┐
│      🍚 餐餐          │
│                      │
│      我的餐券         │
│                      │

│                      │

│  │   使用一張餐券  │  │
│  └────────────────┘  │
│                      │

Touch 一下：

3 → 2

再按：

2 → 1

再按：

1 → 0

到 0：

🚫 今天沒有餐券了

而且程式絕對不能出現 -1 張。

Phase 3｜加入永久記憶 NVS

這是第一版非常重要的功能。

不能發生：

剩 1 張 → 拔電源 → 再開機 → 又變成 3 張。😂

ESP32 本身的 Flash 就能保存資料。

使用 NVS（Non-Volatile Storage）：

使用餐券
   ↓
3 → 2
   ↓
寫入 NVS
   ↓
關機
   ↓
重新開機
   ↓
讀取 NVS
   ↓
仍然是 2 張

因此第一代不需要 microSD。

Phase 4｜加入「發餐券」

現在只有消費，下一步加入管理功能。

例如：

        ↓
     管理模式

┌────────────────┐

└────────────────┘

這樣就形成完整流程：

管理員發券 → 使用者消費 → 系統記錄餘額。

Phase 5｜加入使用紀錄

餐餐開始有「記帳」能力。

例如：

2026/08/28

餘額：2

18:15 使用餐券 1張
餘額：1

我們可以先存在 ESP32。

之後有需要再同步 Cloud。

Phase 8｜加入簡單遊戲

這時 CYD 的價值會完全發揮。
